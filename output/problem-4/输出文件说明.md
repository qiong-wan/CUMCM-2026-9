# output/problem-4 输出文件说明

本文说明 `output/problem-4` 下各类文件的来源、格式、字段含义和读取约定。
对应求解脚本 `src/problem-4/solve_problem4.py`、绘图脚本 `src/problem-4/generate_figures.py`；
当前交付批次为 N=25600、以随机波动为生产主解的完整验证批次。

## 4. `cases/`：完整数值案例

目录命名规则为 `<名称>-<指纹前 16 位>`。指纹由求解源码 SHA-256、原始输入、全部数值与情景参数、依赖版本和数据结构版本共同决定；只有指纹和文件校验全部匹配的已完成案例才可复用。

### 4.1 当前批次案例

| 名称 | 用途 |
|---|---|
| `appendix4_fluct` | 主交付案例（附录 4、实测收缩、AR(1) 随机波动 seed=0、N=25600、时间倍率 0.5） |
| `appendix4_fluct_coarse`、`appendix4_fluct_time` | 主案例空间（N=12800）与时间（倍率 0.25）加密对照 |
| `appendix3_fixed`、`appendix3_shrink`、`appendix4_fixed` | 固定/实测收缩与附录物性对照（末值延拓） |
| `appendix4_last` | 附录 4 收缩、末值延拓对照（原末值主解） |
| `appendix4_mean30` | 附录 4 收缩、末 30 min 均值延拓 |
| `space_n6400`、`space_n12800`、`space_n25600`、`main`、`time_quarter` | 历史末值主族的加密案例，保留供追溯 |

### 4.2 每个案例目录内的文件

| 文件 | 内容 |
|---|---|
| `metadata.json` | 案例完整元数据，见 4.3 |
| `summary.npz` | 压缩摘要，见 4.4 |
| `fields_XXXX.npz` | 完整双场分块，每块 32 个时刻；`times` 形状 (32,)，`states` 形状 (32, 2, N+1)，均为 float64 |
| `failure_state.npz`、`failure.json` | 仅在运行中断或失败时出现，保存最后状态、累计通量、步数和错误 |
| `<名称>-<指纹>-retry-<纳秒>` | 中断后重试生成的新目录，不覆盖原失败证据 |

### 4.3 `metadata.json` 关键字段

| 字段 | 含义 |
|---|---|
| `status` | `COMPLETE` 表示案例文件写入完整；`validation` 固定为 `PENDING`，正式验收状态以 `review/verification.json` 为准 |
| `name`、`identity` | 案例名；`identity` 含 `config`、输入哈希、`solve_code_sha256`、依赖版本 |
| `identity.config` | n、factor、appendix、shrink、tail、horizon、event_tol、method、seed、tau_s、sigma_scale |
| `event` | 事件夹逼：`lower_s`、`upper_s`、`critical_s`、`end_s`、`width_s`、两端符号、裕度、`argmax_x`、`trace` |
| `end_s`、`horizon_reached_without_dryness` | 数值结束时刻；是否 72 h 内未达标 |
| `end_max_C`、`end_argmax_x` | 结束状态全域最大值及位置（归一化半径） |
| `environment_tail`、`environment_mode`、`environment_seed`、`environment_tau_s`、`environment_sigma_scale`、`environment_ar1_phi`、`fluctuation_stats`、`mean30_window` | 环境延拓方式与统计；`fluct` 案例含 AR(1) 系数和去趋势残差统计 |
| `steps`、`rejected_steps`、`step_range_s` | 接受/拒绝步数与步长范围 |
| `max_iterations`、`max_scaled_change`、`max_scaled_residual` | 非线性迭代最坏指标 |
| `property_ranges_T_C_D_a_k` | 全程 T、C、D、a、k 取值范围 |
| `mass_relative_defect`、`heat_relative_defect` 等 | 独立水分/显热平衡缺陷、径向反序、时间增湿、中心差 |
| `runtime_s` | 案例运行秒数 |
| `files` | 本目录所有 `*.npz` 的 SHA-256 |

## 7. 读取约定

1. 正式数值以 `delivery_manifest.json`、`review/verification.json` 及对应案例的 `metadata.json`/`summary.npz`/`fields_*.npz` 为准；`结果与验证.md`、`table6.md` 为自动生成展示件。
2. 所有哈希均在 `metadata.json`、验证报告或交付清单中记录；改动任一数值文件都会使校验失败。
3. `validation` 字段固定为 `PENDING` 是设计如此，案例是否被接受以 `review/verification.json` 中的情景状态为准。
4. `review/verification_pending.json` 是过程文件，不表示最终状态。
5. `cases/` 下可能同时存在历史批次同名案例，按目录指纹区分；不要按名称覆盖。
6. 生产主解采用随机波动 seed=0 的一条固定 AR(1) 路径，用于确定性和事件可复现；末值与末段均值仅作对照，不是随机集合或统计区间。
