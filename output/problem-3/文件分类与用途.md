| 文件 | 类别 | 作用与使用时机 |

| `verify_problem3.py` | 验证入口 | 空间和时间加密、事件精度、物理和守恒检查、独立短时积分对照、输入保护审计；带 `--workbook` 时逐格核查交付表 |

源目录另有工作簿导出必需的 `node_modules/` 依赖联接，见第 7 节。原来存于源目录的成果文档和预览已经迁出，今后的生成文件也写入输出目录。

## 4. output：数值解与计算案例

### 4.1 同一案例的三种文件

每个案例以名称为前缀，通常保留下面三个文件；它们承担不同职责。

| 文件形式 | 内容 | 作用 |
|---|---|---|
| `<案例名>.npz` | 未舍入温度和含水率数组、21 点输出、所存时刻的细网格全场、结束状态与累计诊断 | 再分析、比较及生成成果的数值来源；并非保存了每个内部时间步的所有场 |
| `<案例名>.json` | 网格、时间倍率、环境模式、事件夹逼、步数、迭代和守恒诊断 | 快速查看一次求解的参数和结果；不能单独替代完整验证报告 |
| `<案例名>_event_seed.npz` | 跨越阈值前的完整状态、起点时间和搜索宽度 | 对末期事件进行局部重算和精度检查，不能当成交付终态 |

这些 NPZ 同时保留温度与水分，因为温度参与扩散系数计算和热平衡检查；正式工作簿仍只导出水分。数组含义详见源目录 README 的“NPZ 数组约定”。部分研究案例 JSON 中的 `PENDING_CONVERGENCE` 是单次求解留下的状态，整套已执行检查以 `verification.json` 的分项记录为准。

### 4.2 各案例具体用途

N 表示径向区间数，实际节点数为 N+1；factor 是内部步长计划的倍率，不是输出间隔。last 表示观测结束后同时保持温度和环境水分末值；mean30 表示保持 12600 至 14400 s（含两端、31 个观测）的末段算术均值。两者均保留观测区间的原始分段线性边界。

| 案例前缀 | N | factor | 后续环境 | 定位及是否为完整流程必需 |
|---|---:|---:|---|---|
| `production` | 12800 | 0.5 | last | **正式主解**；必需，是表 5、工作簿和主结论的共同来源 |
| `space400` | 400 | 1 | last | 空间加密第 1 级；必需 |
| `space800` | 800 | 1 | last | 空间加密第 2 级；必需 |
| `space1600` | 1600 | 1 | last | 空间加密第 3 级；必需 |
| `space3200` | 3200 | 1 | last | 空间加密第 4 级；必需 |
| `space6400` | 6400 | 1 | last | 空间加密第 5 级；必需 |
| `space12800` | 12800 | 1 | last | 空间加密第 6 级兼时间加密基准；必需 |
| `time12800quarter` | 12800 | 0.25 | last | 与 space12800、production 组成独立时间加密序列；必需 |
| `mean12800` | 12800 | 0.5 | mean30 | 与 production 同网格和时间设置的正式边界敏感性对照；必需 |

上述 9 个前缀各对应三类文件，共 27 个，均保留以支持正式流程和复核。两组不参与当前正式流程的早期试算已删除，详见第 9 节。

## 5. output：验证和溯源证据

| 文件 | 作用及解释边界 |
|---|---|
| `input_audit.json` | 原始附件字段、数值、缺失、时间顺序和间隔等只读审计结果 |
| `verification.json` | 当前完整数值验证的机器可读报告，包括加密、事件、守恒、趋势、旧结果对照、分项状态及数值验收范围 |
| `workbook_verification.json` | 导出后重读 XLSX，检查表头、距离、时间、每个数值和显示格式，以及与表 5 的一致性 |
| `visual_verification.md` | 实际执行的图表、模板和工作簿视觉检查记录 |
| `near_end_common_fields.npz` | 空间和时间案例在相同末期时刻 205800 s 的细网格全场，用于避免直接比较各自不同结束时刻 |
| `problem2_comparison_snapshot.npz` | 第二问衔接对照实际读取的数值快照；用于说明差异，不作为第三问初始状态或精确真值 |
| `protected_hashes_before.json` | 首次运行建立的保护文件 SHA-256 基线 |
| `protected_hashes_after.json` | 后续保护文件 SHA-256 记录，与基线比较以发现外部变化 |
| `verification_initial_scope_failure.json` | 首次保护检查导致验收受阻的原始记录，保留审计过程，不能冒充最新验证结果 |
| `run_environment.json` | 本次运行的软件版本记录，供复现环境核对 |

`verification.json` 的数值验收 PASS 不覆盖所有事项：完整保护文件比较中，由其他工作更新的第二问文件仍记为 FAIL；未执行验证仍记为 SKIPPED。具体文件和解释见 `结果与验证.md`，不要只取最外层状态解释全部检查。

## 8. 文件如何串联

| 阶段 | 执行入口 | 主要输入 | 主要输出 |
|---|---|---|---|
| 输入审计与各案例求解 | `solve_problem3.py` | 原题和附件、代码中的物性与参数 | 审计与观测副本、各案例的 NPZ/JSON/事件起点 |
| 数值验收 | `verify_problem3.py` | 必需案例、原始输入、保护基线及第二问对照 | verification.json、共同末期截面、对照快照、保护哈希 |
| 结果整理 | `deliver_problem3.py` | 验收报告、production 和 mean12800 | 表 5、完整精度 CSV、载荷、报告、环境记录和图表 |
| 工作簿制作 | `build_workbook.mjs` | 原始模板、workbook_payload.json | result3.xlsx、工具检查记录和工作簿预览 |
| 交付一致性检查 | `verify_problem3.py --workbook` | result3.xlsx、载荷和表 5 | workbook_verification.json，并更新结果报告中的工作簿验证记录 |

`run_all.py` 负责顺序串联上述阶段。仅阅读结果无需运行代码；完整复现应使用源目录 README 的命令。分类索引只说明职责，不替代 `模型与算法说明.md` 的推导或 `结果与验证.md` 的验证结论。
